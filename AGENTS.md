## Daily Living Skills App (Ai therapist)

Tablet app that assesses and trains daily living skills (dressing, eating/drinking, hygiene) for children, in Egyptian Arabic. Native Android (Kotlin, Jetpack Compose) with on-device MediaPipe scoring, a stateless Cloudflare Worker proxy to DeepSeek for doubtful steps, and Python build tools. Planning only so far: architecture `_bmad-output/planning-artifacts/architecture/architecture-Ai therapist-2026-11-11/ARCHITECTURE-SPINE.md` (binding decisions AD-1..AD-12), PRD `_bmad-output/planning-artifacts/prds/prd-Ai therapist-2026-11-11/`, epics `_bmad-output/planning-artifacts/epics.md`, design `docs/designs/daily-living-skills-app.md`.

## Policy

- Never invent clinical content. Assessment steps, domain tags, scoring rules and activities come only from `docs/reference/` and the design's camera-scored step table; if something is missing, say so and stop.
- Write all documents, file names, code and IDs in English; never create Arabic copies of documents. Arabic belongs only in UI strings and audio text in `tools/catalog-builder/strings.ar-eg.json`.
- Keep all child data on the tablet (Room + SQLCipher). Never add a data backend or external dashboard; only cropped frames without identifiers may go to the proxy.
- Doubt is never failure: any uncertainty becomes `cannot_tell`, never `not_done`.
- Never commit secrets: `DEEPSEEK_API_KEY` and `SHARED_SECRET` are Worker secrets, `ELEVENLABS_API_KEY` is an env var only.
- Never log child name, code, frame or request body (Logcat or Worker logs).
- The stack is fixed: Kotlin + Compose (Flutter rejected), Material 3 + adaptive, Navigation 3, Hilt, Coil 3, compose-shimmer, MediaPipe, Room + SQLCipher, Rive, Konfetti, Vico, Cloudflare Worker (TypeScript, `openai` SDK) to DeepSeek `deepseek-flash`, ElevenLabs for one-time audio, Python 3.14 tools. Changing it goes through `bmad-architecture`, not an ad-hoc edit.
- Reuse open source only when it is current and better than building the part; keep its license notices. Store written permissions from repo owners in `docs/permissions/`.
- Work story by story with `bmad-build`, tracked in the sprint status file under `_bmad-output/implementation-artifacts/` (created by `bmad-sprint-planning`).
- Ignore `elephant-goldfish-model/`: an unrelated plugin clone; exclude it from searches and never edit it.

## Where things are

- Clinical sources (assessment scales, scoring rules, treatment plans): `docs/reference/`
- Docs index: `docs/README.md` (brainstorm, design + EGM reviews, clickable wireframes in `docs/wireframes/index.html`)
- Planned layout: `android/`, `proxy/`, `tools/{catalog-builder,audio-gen,art}/`, `art/`, `eval/` — see the spine's Structural Seed.
- Content contract: `assets/catalog/assessment.json` and `activities.json` are generated by `tools/catalog-builder`; never hand-edit them, and never hard-code a step ID, activity ID, threshold or question in Kotlin outside tests.
