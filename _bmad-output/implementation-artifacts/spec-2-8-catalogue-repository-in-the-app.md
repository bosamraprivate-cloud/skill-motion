## Intent

**Problem:** The builder now writes `assets/catalog/{assessment,activities,version}.json`, but the app cannot read them; the runner and screens need typed, ordered content without hard-coding any step or activity.

**Approach:** Extend `catalog/CatalogModels.kt` to match the generated JSON exactly (steps with Arabic text, detector, audio, per-variant media; activities; version info) and add `CatalogRepository` that loads and caches them off the main thread, exposing tasks (grouped, in order), steps, activities and `catalogVersion`, failing loudly on any unknown field or check type.

## Boundaries & Constraints

**Always:** Decode with `ignoreUnknownKeys = false`; an unknown check `type` or field fails with a clear error naming the file (no silent skip). Expose 15 tasks in catalogue order, 147 steps in order within tasks, 148 activities, `catalogVersion`, `complete` flag, and each step's detector with its derived `landmarkers` (pose/hand/none from method + check). Media and audio may be null (dev catalogue, `complete = false`); callers get null, not a crash. Load once on IO, cache in memory, Hilt singleton behind an interface for fakes. A test scans Kotlin sources outside tests and fails on any step-ID or activity-ID literal (pattern from AD-2). No Android types in the models.

**Never:** No hand-written content, no fallback built-in catalogue, no network. No UI in this story.
